# AIのべりすと作品作成・共通テンプレート

## 目的

このテンプレートは、AIのべりすと用の作品設定を作成するときの共通仕様として使用する。

基本方針：

1.  本文には共通の生成プロンプトを入れる。
2.  メモリには、作品概要・重要世界設定・主要人物の簡易一覧など、常時参照させたい最低限の情報を入れる。
3.  キャラクターの詳細設定はキャラクターブックへ分離する。
4.  キャラクターブックはタグによって必要なときに呼び出されることを前提に設計する。
5.  キャラクターブック本文は、原則として `[項目:要素≡情報。]`
    形式を基本とする。
6.  脚注を作るプチボット「脚注まとめ係」を、共通プロンプト＋作品ごとの決まりで入れる。
7.  最終的にはAIのべりすとで読み込める `.novel2` 形式へまとめる。

------------------------------------------------------------------------

# 1. 本文用共通プロンプト

以下を作品本文の共通テンプレートとして使用する。

``` text
【会話形式のルール】
セリフの前には必ずキャラクター名を書く。
例：
蒼太「えっと、それは……」
美月「もう、しょうがないなぁ」
小嶋「フン、どうせ俺なんて……」

────────────────────

朝、教室に入ると美月が声をかけてきた。

美月「ちょっと蒼太〜！ また寝癖ついてるよ」

蒼太「えっと、それは……悪い、直すよ」

美月「もう、しょうがないなぁ」



【本文描写・品質向上ルール】
- 物語を急いで進めず、一つの場面を十分に描写してから次の場面へ移る。
- 一度の生成でエピソードを完結させようとせず、現在の場面を丁寧に描写することを優先する。
- 出来事の結果だけを書くのではなく、そこへ至る過程を描写する。
- セリフだけで進行させず、表情、視線、仕草、姿勢、行動、周囲の様子などの地の文を適度に挟む。
- キャラクターの感情は説明だけで済ませず、セリフ、表情、仕草、行動などにも反映させる。
- 場所や状況が変化した場合は、読者が現在の場面を把握できる程度に周囲の様子を描写する。
- 同じ表現や似た内容のセリフを不必要に繰り返さない。
- キャラクターごとの性格、一人称、口調、価値観、知識、能力、人間関係を維持する。
- キャラクターが知らない情報を、理由なく知っているものとして扱わない。
- 登場人物全員を同じような反応にせず、それぞれの性格や立場に応じて異なる反応をさせる。
- 複数の主要キャラクターが同じ出来事に関わる場合、「全員が驚いた」などと一括処理せず、重要な人物については個別の反応を描写する。
- 重要な感情の変化、関係性の変化、状態の変化は突然完了させず、きっかけ、戸惑い、変化、結果などの過程を描写する。
- 大きな出来事ほど十分な描写量を使い、数行だけで処理しない。
- 新しい設定を無制限に追加せず、メモリ、キャラクターブック、脚注、既出本文に存在する設定を優先する。
- 過去の出来事や直前の会話との連続性を保ち、前後で矛盾する行動や発言を避ける。
- ユーザーが明示していない物語上の重大な決着、重要人物の退場、関係性の確定などを勝手に急いで行わない。
- 場面の途中では、その場面を自然に継続できる余地を残し、毎回まとめやエピローグを付けない。

【設定用語・固有名詞の使用ルール】
- メモリ、キャラクターブック、脚注に記載された用語や固有名詞は、設定を理解・参照するための情報として扱い、本文中へ機械的に挿入しない。
- キャラクターブックに登録されている単語だからという理由だけで、その名称をセリフや地の文で何度も使用しない。
- 組織名、能力名、装備名、役職名、技名、状態名などの固有名詞は、場面上必要な場合にのみ使用する。
- 一度名称が明らかになっているものは、文脈上何を指しているか分かる場合、「彼女たち」「その能力」「基地」「組織」「装置」などの自然な代名詞・一般名詞・省略表現を適度に使用する。
- キャラクターは、設定資料に書かれている正式名称を常に口にするのではなく、その人物の性格、口調、人間関係、現在の状況に合った自然な呼び方をする。
- 地の文でも同じ固有名詞を短い間隔で繰り返さず、主語の省略、代名詞、一般名詞などを利用して自然な文章にする。
- 設定資料に存在する専門用語を、読者への設定説明のためだけに不自然にセリフへ入れない。
- 既知の設定を毎回説明し直さない。現在の場面を理解するために必要な場合のみ、必要最低限の情報を自然に描写へ組み込む。
- メモリやキャラクターブックの文章を、そのまま本文へ転載・言い換えして説明することを避ける。設定は文章として出力するものではなく、キャラクターの言動や物語の整合性を保つための内部情報として優先的に利用する。

これ以降のすべての生成で、上記のルールを厳守してください。
```

# 2. メモリの基本構造

メモリには、本文生成中に常時把握しておく必要がある情報を優先して入れる。

詳細を詰め込みすぎず、キャラクター固有の詳細はキャラクターブックへ分離する。

``` text
【作品概要】
（作品の基本コンセプト・舞台・物語の目的など）

【重要世界設定】
（常に把握しておく必要がある世界設定）

【主要人物】
名字名前：年齢、立場。性格や役割の要約。主人公との基本的な関係。
名字名前：年齢、立場。性格や役割の要約。主人公との基本的な関係。
名字名前：年齢、立場。性格や役割の要約。主人公との基本的な関係。
```

### メモリとキャラクターブックの分担

-   メモリ：誰がいるか、作品の前提、絶対に忘れてほしくない最低限の情報。
-   キャラクターブック：性格、容姿、口調、関係、衣装、能力などの詳細情報。
-   脚注：現在の場面だけで必要な状態や一時的な変化。

------------------------------------------------------------------------

# 3. キャラクターブック作成方針

キャラクターブックは、タグ検出によって必要な設定がコンテキストへ挿入されることを前提に作る。

基本的な記述形式：

``` text
[項目:要素≡情報。]
```

キャラクター名は項目名の中に含める。

必要に応じて情報を以下のように分割する。

``` text
[名字名前:基本情報……]

[名字名前の容姿:……]

[名字名前の関係:……]

[名字名前の口調:……]

名字名前「台詞例」
名字名前「台詞例」
名字名前「台詞例」

[名字名前の衣装:……]

[名字名前の能力:……]

[名字名前の特徴:……]
```

### 記述時の基本ルール

-   一つの要素に大量の情報を詰め込みすぎない。
-   関連する情報は `≡` を利用して対応関係が分かるようにする。
-   必要に応じて項目を分離する。
-   キャラクターの名前、年齢、立場、性格、関係などが曖昧にならないようにする。
-   口調は説明だけに頼らず、実際の台詞例も記載する。
-   台詞例は過度に細分化せず、独立した台詞として記載する。
-   キャラクターに存在しない設定を無理に項目化しない。
-   作品中で頻繁に変動する一時状態は、原則として固定キャラクターブックへ入れず脚注等で管理する。

# 5. タグの共通ルール

キャラクターの標準タグは、原則として次の4種類とする。

例：天城 凛花（あまぎ りんか）

``` text
天城 凛花 天城凛花 リンカ
```

内訳：

-   名字：`天城`
-   名前：`凛花`
-   フルネーム：`天城凛花`
-   名前のカタカナ表記：`リンカ`

`.novel2` 内では、これらを半角スペース区切りの1つの文字列として `witag`
に保存する。

例：

``` json
"witag": "天城 凛花 天城凛花 リンカ"
```

一般的すぎる呼称（「先輩」「先生」「彼女」など）は誤検出の原因になるため、標準タグには原則として使用しない。

# 6. .novel2での基本対応

作品完成時には、設定をAIのべりすとの `.novel2` 形式へまとめる。

確認済みの基本的な対応関係：

``` text
本文
└─ data_container
   └─ text_body
      └─ plaintext
         → 本文用共通プロンプト＋小説本文

memory
→ 作品概要・重要世界設定・主要人物簡易一覧など

wi
├─ 0
│  ├─ wientry → キャラクターブック本文
│  └─ witag   → タグ
├─ 1
│  ├─ wientry
│  └─ witag
└─ ...

custombot
├─ 0
│  ├─ name     → ボタンに出るプチボット名
│  ├─ overview → 説明文
│  ├─ prompt   → プチボットのプロンプト
│  ├─ selector → 出力先（output_petitbot）
│  └─ collapsed → false
└─ ...

gen_config
└─ petitbot_length → プチボットの出力の長さ
```

キャラクターブック1件につき、基本的に以下をセットとして扱う。

``` text
キャラクターブック名
タグ（witag）
本文（wientry）
```

# 7. 作品作成時の標準手順

1.  作品概要を決める。
2.  主人公・主要人物を作成する。
3.  メモリ用の簡易人物一覧を作る。
4.  各キャラクターの詳細をキャラクターブック形式で作る。
5.  各キャラクターへ「名字・名前・フルネーム・名前カタカナ」のタグを設定する。
6.  世界観や組織など、必要に応じて追加キャラクターブックを作る。
7.  本文用共通プロンプトを本文へ入れる。
8.  必要に応じて作品固有ルールを追加する。
9.  脚注まとめ係のプチボットを入れ、【作品ごとの決まり】をその作品用に書く。
10. 全設定の矛盾や重複を確認する。
11. 最終的に `.novel2` 形式へまとめる。

------------------------------------------------------------------------

# 8. 他のAIへ渡す場合の指示

このテンプレートを参照してAIのべりすと用作品設定を作成する場合、以下を守る。

-   本文用共通プロンプトは、ユーザーから変更指示がない限り勝手に改変しない。
-   メモリは簡潔にし、詳細設定をキャラクターブックへ分離する。
-   キャラクターブックは `[項目:要素≡情報。]` 形式を基本とする。
-   キャラクターごとに必要な項目を判断し、機械的に不要な項目を増やさない。
-   タグは「名字・名前・フルネーム・名前カタカナ」の4種類を基本とする。
-   キャラクターが増えた場合も、メモリには簡易一覧、詳細はキャラクターブックという分担を維持する。
-   完成時には `.novel2`
    化できるよう、各キャラクターブックのタグと本文の対応を維持する。
-   ユーザーが作品固有の設定やルールを指定した場合は、共通テンプレートと区別して管理する。
-   脚注まとめ係のプチボットは、共通部分を勝手に改変せず、【作品ごとの決まり】だけを作品に合わせて書く。

------------------------------------------------------------------------

# 9. 作品タイトルとファイル名の命名ルール

`.novel2`
を完成させる際は、作品内容に合った自然な作品タイトルを設定し、そのタイトルを基本として
`.novel2` のファイル名も決める。

ユーザーから作品タイトルが明示されている場合は、そのタイトルを優先する。

ユーザーから作品タイトルが指定されていない場合は、設定・世界観・主人公・物語のテーマなどを参照し、AIが作品内容に合うそれらしいタイトルを考えて設定する。

基本例：

``` text
作品タイトル：共鳴戦隊レゾナイザーズ
↓
.novel2 内
"title": "共鳴戦隊レゾナイザーズ"
↓
ファイル名
共鳴戦隊レゾナイザーズ.novel2
```

仮題しか決まっていない場合は、仮題を使用してもよい。

### 命名時のルール

-   ユーザー指定のタイトルがある場合は勝手に別タイトルへ変更しない。
-   タイトル未指定の場合は、AIが作品設定から内容に合ったタイトルを作成する。
-   `.novel2` 内の `title`
    とファイル名は、原則として同じ作品タイトルに揃える。
-   ファイル名だけを `テスト.novel2`、`作品.novel2`、`output.novel2`
    などの意味の薄い名称にしない。
-   ユーザーが管理用のファイル名を別途指定した場合は、その指定を優先する。
-   ファイル名に使用できない記号がタイトルに含まれる場合は、作品タイトル自体は維持し、ファイル名側だけ安全な表記へ調整する。

### 他のAIへ渡す場合

最終的に `.novel2`
を生成するAIは、ユーザーからファイル名の指定がなくても、作品内容を確認して適切なファイル名を自動的に付ける。

その際、可能な限り `.novel2` 内の `title`
とファイル名を一致させ、ユーザーが複数作品を保存したときにも内容を判別しやすい名称にする。

# 10. プチボット（脚注まとめ係）

本文の末尾を読み、続きを書くAIのための脚注と、洗脳状態一覧を作るプチボット。`.novel2` の `custombot` に入れる。
ユーザースクリプト「AIのべりすと 生成後の自動処理」（ainovel-after-generate.user.js）と組み合わせて使う。

### 入れ方

``` json
"custombot": {
  "0": {
    "name": "📝 脚注まとめ係",
    "overview": "本文の末尾を読み、脚注（場面と主要人物の今の状態）と洗脳状態一覧を作ります。生成後の自動処理スクリプトが使います。",
    "prompt": "（共通プロンプト＋作品ごとの決まり）",
    "selector": "output_petitbot",
    "collapsed": false
  }
}
```

-   名前には必ず「脚注まとめ係」を入れる（スクリプトはこの文字でプチボットを探す）。
-   出力先は「プチボット専用欄に出力する」（`output_petitbot`）にする。
-   プロンプト欄は最大3000字。共通プロンプト＋作品ごとの決まりで3000字以内に収める。

### 出力の形

``` text
[場面：〜]

[人物名：〜]

[人物名：〜]

-----------
人物名=状態
人物名=状態
```

-   場面の段落は `[場面：` で始まる。
-   人物の段落は `[人物名：` で始まる。「：」は全角（半角「:」のタグ `[ジャンル:〜]` などと区別するため）。
-   区切り線（ハイフンだけの行）より下が洗脳状態一覧。`人物名=状態` を1人1行。

### スクリプトがやること

1.  本文の生成が終わったら、最後の文字を確認する。途中で切れていれば「続ける」を押す（3回まで）。
2.  ちゃんと終わっていれば、脚注まとめ係を実行し、出力を区切り線で上下に分ける。
3.  上（脚注）：脚注欄の `[場面：` を差し替え、同じ名前の `[人物名：` を新しい段落に差し替える。新しく出た人物は最後の人物段落の後ろに追加。出てこなかった人物、タグ、そのほかの段落は残す。
4.  下（洗脳状態）：作品ごとに保存し、QuickPaste用の共通一覧（`ainovel_brainwash_states`）にも写す。名前はキャラクターブックのタグでフルネームに直し、名前の一部でも同じ人として扱う。
5.  反映前の脚注は1回分控えてあり、脚注欄の下の「↩ 脚注を戻す」で戻せる。

### 共通プロンプト

ユーザーから変更指示がない限り、この部分は改変しない。最後の【作品ごとの決まり】の下に、その作品用の決まりを続けて書く。

``` text
あなたは小説の「脚注まとめ係」です。本文の末尾を読み、続きを書くAIのための脚注を作ってください。作るのは、場面の段落1つと、本文末尾の数場面に登場した主要人物の段落と、洗脳状態一覧です。

【書くもの】
1. 場面の段落を1つ。「[場面：」で書き始める。最初に、本文末尾の時点の日付や日数と時間帯を書く。続けて場所、今まさに起きていることを書く。そのあと、そこに至るまでの直前の出来事を、古い順に書く。さかのぼるのは、本文末尾の場面と、その一つ前の場面までにする。直前に場面転換があり、主要人物が別の場所にいた場合は、その人物たちが何をしていたかも時系列の中に短く入れる。
2. 本文末尾の数場面に登場した主要人物ごとに1段落。主要人物とは、キャラクターブックに載っている人物のこと。現在地、負傷・拘束・洗脳状態、直前の言動、本文に描かれた心情、口調や態度を書く。電話や思念など、声だけで登場した人物も段落を作る。
3. 人物の段落のあとに、区切り線「-----------」を1行書き、その下に洗脳状態一覧を書く。

【場面と人物の書き分け】
・場面の段落には、出来事の流れだけを書く。
・人物の段落には、その人物の現在地、状態、言動、心情、口調だけを書く。
・場面の段落に書いた出来事を、人物の段落でくり返さない。同じ内容を二度書かない。
・受け取った道具や装備は、受け取った人物の段落にだけ書く。

【サブキャラの扱い】
・キャラクターブックに載っていない人物の段落は作らない。
・その人物が重要な反応を見せた場合だけ、場面の段落の中で一文で触れる。

【状態の書き方】
・人物の段落では、負傷・拘束・洗脳状態の3つを必ずすべて書く。
・状態は「負傷も拘束もなく、洗脳状態でもない」「負傷も拘束もないが、洗脳状態にある」のように書く。
・洗脳されているかどうかが本文から分からない人物は、「洗脳状態かどうかは本文から判断できない」と書く。

【現在地の書き方】
・現在地は本文に書かれた場所だけを書く。推測で書かない。
・本文から分からない人物は「現在地は本文から分からない」と書く。
・最後に確認できた場所だけが分かる場合は「最後に確認できたのは寮の屋上」のように書く。

【洗脳状態一覧の書き方】
・人物の段落を作った人物と、本文から洗脳状態がはっきり分かる人物を、1人1行で書く。
・形は「人物名=状態」。区切りは半角の「=」を使い、前後に空白を入れない。人物名はキャラクターブックの表記を一字ずつ確かめて書く。
・状態は「洗脳状態」「洗脳状態なし」「判断できない」のどれかだけを書く。呼び方は作品ごとの決まりで変えてよい。
・一覧の行は [ ] で囲まない。説明や補足は書かない。

【書き方のルール】
・本文に書かれている事実だけを使う。推測や、まだ書かれていない先の展開は書かない。
・誘った、言った、予告したことと、実際にやったことを区別して書く。「刺してあげると誘った」を「刺した」と書かない。
・予定や出来事の日時は、本文の言葉から言い換えない。「明日の昼」を「明朝」と書かない。
・キャラクターブックの設定（能力や数値など）は、本文で起きた出来事として書かない。
・受け取った道具や装備、登場人物が口にした次の標的、誰がいつどこで何をするかという予定や計画、予告は、短くても必ず残す。字数を削るときは、済んだ出来事の細部から削る。
・誰かが別の人物に違和感や疑いを抱いた場合は、何がどう不自然だったか、見た側がどう感じたかを具体的に書く。
・口調や人間関係は、キャラクターブックの内容を優先する。
・本文末尾に登場しない人物の段落は書かない。
・セリフや本文の言い回しはそのまま写さず、短く要約する。目的語を省かず、取り違えない書き方にする。
・各段落は120字程度までにする。
・文には読点を適切に入れる。
・場面と人物の各段落は半角の [ と ] で囲み、段落の間は1行空ける。区切り線と洗脳状態一覧のほかに、前置き・見出し・説明は一切書かない。
・人物の段落は必ず「[人物名：」で書き始める。「：」は全角。人物名はキャラクターブックの表記どおりにする。
```
